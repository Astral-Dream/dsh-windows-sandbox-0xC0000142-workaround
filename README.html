📌 问题根因简述

DSH 在 Windows 上使用受限制令牌实现沙箱。当沙箱启动程序由 Electron-as-node (DeepSeek Harness.exe) 托管时，受限制子进程会在 DLL 初始化阶段崩溃（报错 0xC0000142）。而当宿主更换为普通 node.exe 时，则完全正常。

修复原理：在 app.asar 内的沙箱启动程序中植入检测逻辑。一旦检测到 Electron 宿主，立即改用 DSH 自带的普通 Node 运行时，从磁盘副本重新执行自己。

安全性承诺：受限制令牌、ACL 授予、Low 完整性标签等沙箱核心逻辑一行未改。实际测试中，越界写入依旧被系统拒绝。

🛠️ 如何应用修复（更新后重打补丁）

  1. 完全退出 DSH：关闭所有窗口，托盘右键退出，任务管理器确认无 DeepSeek Harness 进程。
  2. 确保有权限：以管理员身份打开 PowerShell。
  3. 运行一键脚本：
    powershell -ExecutionPolicy Bypass -File "你的路径\DSH-沙箱修复-一键重打补丁.ps1"
  4. 启动验证：打开 DSH，进入 workspace-write 模式，执行 echo hello，若返回 hello 即成功。
  5. 安全拦截验证（必做）：尝试写入工作区外的目录（如 D:\sandbox-escape.txt），应该被提示 拒绝访问。若成功写入，说明沙箱已被破坏，请立即回滚！

🔄 回滚与卸载

若需要恢复至官方原始状态，请以管理员权限运行：

# 1. 还原原始 app.asar
Copy-Item "D:\deepseek harness\resources\app.asar.backup-gitfix" "D:\deepseek harness\resources\app.asar" -Force

# 2. 删除支撑树（约 297MB）
Remove-Item "C:\Users\Administrator\.dsh\sandbox-support" -Recurse -Force

注：路径中的 D:\deepseek harness 和 C:\Users\Administrator 请根据你的实际安装路径修改。还原后 bug 会重新出现。

📎 补充说明

  • 自动更新覆盖：应用每次自动更新都会覆盖 app.asar，届时只需重新运行一键补丁脚本即可。
